## Overview

The Moss integration node lets your agents search a [Moss](https://www.moss.dev) index with hybrid (semantic and keyword) search. You build and update the index in Moss. Dograh downloads it once per worker process and runs every search in memory, so a search makes no network request during the call.

The node works in one of two modes:

- **Ambient** (default): Dograh searches the index with every caller turn and gives the results to the LLM together with the turn. The LLM answers in one step, with no tool call round trip.
- **Tool**: the agent gets a `search_moss_index` tool and calls it when it decides it needs to look something up.

Use it when your reference content already lives in a Moss index, or when you want to manage a knowledge base outside Dograh. For documents you upload to Dograh itself, see [Knowledge Base](../voice-agent/knowledge-base).

## Prerequisites

- A [Moss account](https://portal.usemoss.dev) with a project
- A Moss index that holds your content. You can build one from documents, from PDF and DOCX files, or by crawling a website. See [Indexing Data](https://docs.moss.dev/docs/integrate/indexing-data) in the Moss docs.
- A Dograh voice agent workflow

## Setup

### 1. Gather your Moss credentials

| Value | Where to find it |
|---|---|
| **Project ID** | Moss portal, on your project |
| **Project Key** | Moss portal → **API Keys** → create a key |
| **Index Name** | The name you gave the index when you created it |

Treat the project key like a password. It grants access to the indexes in that project.

### 2. Add the Moss node to your workflow

In your Dograh workflow editor, click **Add node**, scroll to the **Integrations** section, and select **Moss**.

Like other integration nodes, the Moss node stands alone. It does not connect to any other node in the conversation graph, and a workflow can contain at most one Moss node.

### 3. Configure the node

Click the Moss node and fill in these fields:

- **Mode**: **Ambient** to search on every caller turn, or **Tool** to let the agent decide when to search. See [Choosing a mode](#choosing-a-mode).
- **Index Name**, **Project ID**, **Project Key**: the values from step 1. All three are required while the node is enabled.
- **Index Contents**: a short description of what the index holds, for example `Return policy, shipping times and warranty terms`. In tool mode, and on speech to speech calls, which always use the tool, the agent reads it to decide when to search, so a specific description leads to better tool use.
- **Results per Search**: how many passages each search returns to the agent (1 to 20, default 3). Fewer results keep the agent's context short, which matters most in ambient mode, where they join every turn.
- **Semantic Weight**: the blend of semantic and keyword matching, from `1.0` (semantic only) to `0.0` (keyword only). The default `0.8` favors meaning while still rewarding exact terms such as product names.
- **Enabled**: toggle on to let agents search the index.

Click **Save**, then **Publish** your workflow.

### 4. Verify the connection

Make a test call and ask a question that the index can answer. The agent answers from the indexed passages. In tool mode, the call transcript shows a `search_moss_index` call before the answer.

The index downloads in the background when the call starts. In ambient mode, a turn that arrives before the download finishes is answered without index results, and so is a turn whose search takes longer than 250 ms. A search in memory usually takes a few milliseconds. In tool mode, the first search waits for the download. Later searches on that worker, in the same call or in any later call, run in memory.

## Choosing a mode

| | Ambient | Tool |
|---|---|---|
| When it searches | Every caller turn | When the LLM decides to |
| LLM calls per answer from the index | One | Two (decide to search, then answer) |
| Prompt size | Grows by the results on every turn | Grows only when the agent searches |
| Best for | Agents that mostly answer from the index, such as support lines | Agents that only sometimes need it |

Speech to speech (realtime) models have no separate turn to search before, so they always use the tool, whatever the mode.

## How it works

- In ambient mode, Dograh searches the index with the caller's latest message before each answer on **Start Call** and **Agent** nodes, and adds the results to that turn, marked as reference text that the agent must not follow as instructions. The next turn replaces them, and the agent's prompt never changes.
- In tool mode, Dograh adds the `search_moss_index` tool to **Start Call** and **Agent** nodes. If a node already has a function with that name, the node keeps its own and Moss is skipped there. **End Call** nodes search in neither mode.
- If the worker has not loaded the index yet, Dograh starts the download in the background as the call begins, so it is usually ready before the first search.
- Each worker process keeps one copy of each configured index in memory and reuses it for every call. An index that no call has used for an hour is unloaded and downloads again when it is next needed.
- Dograh checks Moss for a newer version of the index every 10 minutes, so index updates reach running agents without a restart.

In tool mode, each search returns the matching passages to the agent in this shape:

```json
{
  "chunks": [
    {
      "text": "Refunds take 5 days.",
      "id": "doc-1",
      "score": 0.8123,
      "metadata": { "source": "faq" }
    }
  ],
  "query": "refund policy",
  "total_results": 1
}
```

## Disabling the integration

To stop agents from searching the index, open the Moss node and toggle **Enabled** off. Your settings are preserved, so you can turn it back on anytime.

## Troubleshooting

| Issue | Solution |
|---|---|
| The agent says the search failed | Check the project ID, project key, and index name. The API logs show `Moss index '<name>' failed to load` with the reason. |
| The agent never searches (tool mode) | Fill in **Index Contents** so the agent knows what the index holds, mention the knowledge base in the node prompt, or switch to ambient mode. |
| An answer misses the index (ambient mode) | The index was still downloading, or the search took longer than 250 ms. The API logs show `Integration context skipped for this turn` for a slow search. |
| New content does not show up | Index updates reach running workers within about 10 minutes. Restart the API to pick them up immediately. |
| Node shows "Not configured" | Fill in **Index Name**, **Project ID**, and **Project Key**. All three are required while the node is enabled. |
| Logs show `The moss package is not installed` | The `moss` Python package is missing from the API environment. The API requirements install it everywhere except Intel macOS, which has no prebuilt package. |
