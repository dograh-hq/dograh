Dograh ships official SDKs for **Python** and **TypeScript** that wrap the Dograh REST API and the workflow builder. Use them to create or edit agents, place outbound calls, and inspect runs from your own code.

- **Python** — [`dograh-sdk`](https://pypi.org/project/dograh-sdk/) on PyPI
- **TypeScript** — [`@dograh/sdk`](https://www.npmjs.com/package/@dograh/sdk) on npm

Both packages are generated from the same backend OpenAPI spec, so the method surface is equivalent — only the naming convention differs (`snake_case` in Python, `camelCase` in TypeScript).

## Install

<CodeGroup>
```bash Python
pip install dograh-sdk
```
```bash TypeScript
npm install @dograh/sdk
```
</CodeGroup>

## Authenticate

Generate an API key at [`/api-keys`](https://app.dograh.com/api-keys) (or `http://localhost:3010/api-keys` for self-hosted). See [API Keys](/configurations/api-keys) for details.

Both SDKs read the API key from the `DOGRAH_API_KEY` environment variable by default, and the base URL from `DOGRAH_API_URL` (defaults to `http://localhost:8000`). You can also pass them explicitly.

<CodeGroup>
```python Python
from dograh_sdk import DograhClient

client = DograhClient(
    base_url="https://app.dograh.com",
    api_key="YOUR_API_KEY",
)
```
```typescript TypeScript
import { DograhClient } from "@dograh/sdk";

const client = new DograhClient({
    baseUrl: "https://app.dograh.com",
    apiKey: "YOUR_API_KEY",
});
```
</CodeGroup>

<Note>
For self-hosted deployments, swap `baseUrl` for your backend URL (e.g. `http://localhost:8000`).
</Note>

## Quick tour

List the agents in your workspace:

<CodeGroup>
```python Python
workflows = client.list_workflows()
for wf in workflows:
    print(wf.id, wf.name)
```
```typescript TypeScript
const workflows = await client.listWorkflows();
for (const wf of workflows) {
    console.log(wf.id, wf.name);
}
```
</CodeGroup>

## For AI agents

The Python and TypeScript clients are generated from routes tagged `@sdk_expose` on the API. A runnable walkthrough — create an agent with the Workflow SDK, save a draft, validate, publish, then optionally create and start a campaign — lives in `examples/python/publish_agent_and_campaign.py` (TypeScript twin: `examples/typescript/publish_agent_and_campaign.ts`).

Methods added for that flow, in addition to `create_workflow`, `update_workflow`, `get_workflow`, and `list_workflows` (camelCase on TypeScript, for example `validateWorkflow`):

- Workflows: `validate_workflow`, `publish_workflow`, `list_workflow_runs`, `get_workflow_run`
- Tools: `get_tool`, `update_tool`, `delete_tool` (archives the tool)
- Campaigns: `list_campaigns`, `create_campaign`, `get_campaign`, `start_campaign`, `pause_campaign`, `resume_campaign`, `get_campaign_progress`
- Folders: `list_folders`, `create_folder`

`create_workflow` publishes version 1 immediately. Saving a workflow definition with `save_workflow` / `update_workflow` writes a draft (a name-only update does not). Call `publish_workflow` after `validate_workflow` before that draft serves calls. An optional body sets `version_name` and `change_description` as release notes (`publishWorkflow` on TypeScript). Creating a campaign still needs a CSV `source_id` from the Dograh uploader and a telephony configuration on the organization.
